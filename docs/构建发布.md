## 一、本地构建

### 环境要求

| 项 | 要求 | 备注 |
| --- | --- | --- |
| Go | **1.25+** | `go version` |
| Windows CGO | MSYS2 **UCRT64** + `gcc` | Fyne 需要；`gcc` 必须在 PATH 里 |
| Ubuntu CGO | `build-essential libgl1-mesa-dev xorg-dev` | 同上 |

### 编译

```bash
# 桌面应用（GUI 子系统：Windows 双击不弹黑框）
go build -ldflags "-H windowsgui" -o merger.exe ./cmd/merger

# 命令行工具箱
go build -o toolbox.exe ./cmd/toolbox

# 画板
go build -ldflags "-H windowsgui" -o paint.exe ./cmd/paint
```

### 测试与静态检查

```bash
go test ./...
go vet ./...
```

### 交叉编译（不需要 Docker）

`toolbox` 与 `paint` 只依赖标准库（除 gopsutil 外），可以直接交叉编译：

```bash
# Linux amd64
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o toolbox-linux-amd64 ./cmd/toolbox

# Linux arm64（RDK / Jetson）
GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -o toolbox-linux-arm64 ./cmd/toolbox
```

> ⚠️ **桌面应用 `merger` 需要 cgo**（Fyne → OpenGL），不能 `CGO_ENABLED=0` 交叉编译。
> Linux 版本请用 CI（原生 runner）或本机 Docker 方案。

## 二、CI 流水线

仓库有两个 workflow，职责分离：

### `build.yml` —— 测试门禁

| 触发 | 行为 |
| --- | --- |
| `push` 到 `main` | 编译 + 测试 |
| `pull_request` | 编译 + 测试 |
| `workflow_dispatch` | 手动触发 |

做三件事：

1. **静态检查**：`go vet ./...`
2. **单元测试**：`go test ./...`
3. **交叉编译冒烟**：确认 4 个目标平台都能编译过

> **门禁的意义**：本地能过、CI 不能过的问题，本质是「本地有、干净 checkout 没有」。
> CI 的价值就在于它是**干净环境**。详见下方「常见坑」。

### `release.yml` —— 建包 + 发布

| 触发 | 行为 |
| --- | --- |
| `push` tag `v*` | 构建 → 上传 Release（含所有平台安装包 + SHA256SUMS.txt） |
| `workflow_dispatch` | 只出 artifact，不发 Release |

产物：

```
merger-windows-amd64.zip
merger-linux-amd64.tar.gz
merger-linux-arm64.tar.gz
toolbox-windows-amd64.zip
toolbox-linux-amd64.tar.gz
toolbox-linux-arm64.tar.gz
paint-windows-amd64.zip
paint-linux-amd64.tar.gz
paint-linux-arm64.tar.gz
SHA256SUMS.txt
```

## 三、发一个版本

```bash
# 1. 确认工作区干净、测试通过
git status
go test ./...

# 2. 打 tag
git tag -a v1.0.0 -m "v1.0.0: 工具箱重构，Python 工具全部迁移到 Go"
git push origin main --tags

# 3. 等 CI 跑完，到 Releases 页面确认
```

`release.yml` 会在 tag 上自动创建 Release，并把四个平台的包一起附上。

## 四、本地复现 CI（可选）

如果想完全复现 CI 的构建产物，可以用 `fyne-cross`（需要 Docker）：

```powershell
# Windows（生成安装包，不只是裸 exe）
go run github.com/fyne-io/fyne-cross@latest windows -arch=amd64 -name "提示词工具箱" -icon ico/icon.png -release

# Linux amd64 + arm64
go run github.com/fyne-io/fyne-cross@latest linux -arch=amd64,arm64 -name "提示词工具箱" -icon ico/icon.png -release
```

产物在 `fyne-cross/dist/`。

> macOS **不能**在普通 Windows/Linux 主机上合法完整交叉编译
> （需要 Apple SDK 与 Xcode 许可）。因此 CI 在 `macos-15` / `macos-15-intel`
> runner 上原生构建。

## 五、常见坑

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| `go build` 报 `gcc: not found` | 没装 MSYS2 / gcc 不在 PATH | 装 MSYS2 UCRT64，把 `C:\msys64\ucrt64\bin` 加进 PATH |
| Linux runner 上 `libGL.so.1: cannot open` | 缺 OpenGL 头文件 | workflow 里 `apt install libgl1-mesa-dev xorg-dev` |
| 桌面程序双击闪黑框 | 默认是控制台子系统 | 加 `-ldflags "-H windowsgui"` |
| 交叉编译后启动就崩 | 用了 `CGO_ENABLED=0` 编 Fyne | 桌面程序必须带 cgo，改用 CI 原生构建 |
| Release 里缺某个平台 | 该 job 失败被 `needs` 卡住 | 看 Actions 页面上失败 job 的日志 |
| `.exe` 被误提交进仓库 | `.gitignore` 规则被覆盖 | 提交前 `git status` 看一遍 |

### 取 CI 日志

```bash
# 每个 step 的结论一眼可见，不用翻日志
curl -sSL -H "Authorization: token $GITHUB_TOKEN" -H "User-Agent: chk" \
  "https://api.github.com/repos/XiaoYuyu520520/Copy-Paste-Mutools/actions/runs/<run_id>/jobs" | jq '.jobs[] | {name, conclusion}'

# 完整日志（zip）
curl -sSL --max-time 180 -H "Authorization: token $GITHUB_TOKEN" -H "User-Agent: chk" \
  "https://api.github.com/repos/XiaoYuyu520520/Copy-Paste-Mutools/actions/jobs/<job_id>/logs" -o job.log
```

> 注意：`/actions/jobs/<id>/logs` 会 **302 到 blob 存储**，用 urllib 跟随时
> `Authorization` 头会被带到新域导致 **403**；用 `curl`（默认不把自定义头
> 转发到别的主机）就没事。

## 六、图标

```bash
# 从 ico/default_icon.ico 生成 Windows 资源对象
windres -J rc -O coff -o app_icon_windows_amd64.syso app.rc

# 或用项目自带的工具生成 png
go run ./cmd/mkicon -src ico/default_icon.ico -png ico/icon.png
```

`.syso` 已随仓库提供，`go build` 会自动链接。
