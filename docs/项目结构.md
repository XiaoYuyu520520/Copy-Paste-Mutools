## 分层设计

```
┌─────────────────────────────────────────┐
│  cmd/            入口层：只做参数解析     │
├─────────────────────────────────────────┤
│  internal/ui    界面层：Fyne 组件编排     │
│  internal/toolbox/cli  分发层            │
├─────────────────────────────────────────┤
│  internal/data  业务逻辑层（纯函数，可测） │
│  internal/toolbox/*  各工具逻辑层         │
├─────────────────────────────────────────┤
│  internal/netscan  引擎层：并发扫描        │
│  internal/render   服务层：HTTP + 前端     │
└─────────────────────────────────────────┘
```

**核心原则**：`data` 与各工具的逻辑层**不依赖界面**，因此可以脱离 GUI 直接跑单测。
`internal/data` 里的合并规则、目录树生成都是纯函数，输入相同则输出相同。

## 关键设计取舍

### 1. 为什么把 `netspeed` 并入主模块？

它原本是独立模块（`module netspeed`），有自己的 `go.mod` 与前端构建链。
并入主模块后：

- 前端 `dist/` 通过 `go:embed` 内嵌 → **单文件部署**
- 不再需要 `npm install && npm run build` 才能用
- 依赖从 2 个模块降到 1 个，`go.sum` 统一管理

前端源码（Vue）保留在旧目录的归档里；`dist/` 是构建产物，已入库。

### 2. 为什么用 `gopsutil` 而不是自己实现？

`读取设备信息.py` 原本依赖 `psutil` + `wmi` + `GPUtil` 三个包，
而这三个在不同平台上的可用性还不一致。`gopsutil` 是它们的 Go 对应物，
纯 Go 实现、跨平台一致、维护活跃，比自己读 `/proc` + 调 WMI 更可靠。

**代价**：多了一个直接依赖。但它在 CI 上是纯 Go 编译，不需要 cgo。

### 3. 为什么命令统一到一个 `toolbox`？

原来的工具散在十几个目录里，各自是独立脚本。用户要记住十几个不同的调用方式。
统一之后：

```bash
toolbox tree
toolbox cpubench
toolbox sysinfo --json
```

`toolbox --help` 就是完整索引。实现上每个子命令仍在自己的包里，
`cli` 包只负责解析参数和分发 —— 保持可测试性与单一职责。

### 4. 为什么保留 `legacy/python/`？

迁移后直接删掉会丢失**协议细节**（如雷达解码、ROS2 话题解析），
这些是重新实现时唯一的参照。归档保留源码但**不参与构建**，
也不进入 CI 的测试路径。

### 5. 前端资源怎么管理？

所有 Web 前端都通过 `go:embed` 内嵌：

| 前端 | 位置 |
| --- | --- |
| 网速测试（Vue 构建产物） | `internal/netspeed/web/netspeed/dist/` |
| 文件共享 | `internal/toolbox/webassets/share/` |
| 性能监视器 | `internal/toolbox/webassets/monitor/` |

这样任何一个可执行文件都是**自包含**的，不依赖旁边的目录结构。

## 模块划分依据

| 包 | 依赖方向 | 能否独立测试 |
| --- | --- | --- |
| `internal/data` | 只依赖标准库 | ✅ 无需 GUI |
| `internal/ai` | 只依赖标准库 | ✅ |
| `internal/toolbox/*` | 依赖标准库 + gopsutil | ✅ 无需 GUI |
| `internal/netscan` | 只依赖标准库 + x/sys | ✅ |
| `internal/render` | 只依赖标准库 | ✅ |
| `internal/chat` | 只依赖标准库 + internal/ai、data | ✅ |
| `internal/theme` | 只依赖 Fyne 主题接口（桌面端与 Android 共用调色板） | ✅ |
| `internal/ui` | 依赖 Fyne + 上述各层 | ⚠️ 需要图形环境 |
| `cmd/*` | 依赖 internal | — |
